Search and Content Refresh Opportunity Scoring

Capstone research paper | Machine Learning

1. Title and Abstract

This study asks whether search and content signals can help identify pages that may deserve a content refresh or improvement. It uses the FlyRank ML Internship dataset and evaluates a scoring model using a client-holdout validation design. A Random Forest model achieved a ROC-AUC of 0.885923, while the transparent baseline achieved 0.915891 on the same test split. Therefore, the model did not outperform the baseline in this evaluation. The results are intended to support a review queue, not to prove that a page needs a refresh or that a change will cause better search performance.

2. Introduction / Problem Statement

Content teams may have many pages to review and limited time to improve them. This project supports the decision of which pages should be reviewed first for a possible content refresh or improvement.

The project uses available search signals to create a prioritization approach. The output is decision-support information for human review, not an automatic instruction to change a page.

3. Data

The analysis uses the FlyRank ML Internship warehouse release, including the fact_content_daily_performance table. The selected analysis window is March 1–31, 2026.

One row represents one content item for one client on one report date. The selected search features are:

  • gsc_impressions
  • gsc_clicks
  • gsc_avg_position

Client names, identifying information, private queries, and future-period information were excluded from the public-facing analysis. The modeling dataset contained 320,048 rows. The average-position feature had 198,334 missing values; the other selected fields had no missing values in the reported check.

The results reflect this dataset and analysis window; they should not be assumed to represent every website or time period.

4. Methodology

The task was framed as scoring pages for review priority. The target was whether a content item received at least one Google Search Console click in the seven days after the scoring date.

The selected features were current search impressions, clicks, and average position. A transparent baseline ranked pages using current impressions. The final model was a Random Forest classifier. Both approaches were evaluated on the same client-holdout test split.

The training set contained 194,613 rows from 41 clients, and the test set contained 125,435 rows from 11 held-out clients. Missing average-position values were handled using a training-data-based median imputation approach. Future-period fields were excluded to reduce leakage risk.

6. Limitations and Honest Framing

  • The analysis identifies associations and patterns; it does not establish that a content change causes a search-performance improvement.
  • Search history and data availability may differ across clients and content items.
  • Some early records may have incomplete engagement history.
  • The available query window may overlap with the analysis period, which limits how future outcomes should be interpreted.
  • A high score is a prediction signal for review, not proof that a page is outdated or needs a refresh.
  • The baseline performed better than the model on the reported test split.

7. Ranked Recommendations

The following action playbook describes how a team can use the output as a review process. It does not identify or expose individual client pages.

  1. Review the highest-scoring pages: inspect the page’s purpose, accuracy, and current search performance before deciding whether to update it.
  2. Check the search evidence: compare impressions, clicks, and average position to understand the signals behind the review priority.
  3. Choose an appropriate action: consider improving, protecting, monitoring, or leaving the page unchanged based on human review.
  4. Record the decision: document the reason for the action and the evidence considered.
  5. Monitor after any change: review later performance without assuming that the change alone caused the result.

The top-scoring records included tied scores, so a score alone should not be treated as a unique ordering of every page. Human review and additional context are needed to resolve ties.
